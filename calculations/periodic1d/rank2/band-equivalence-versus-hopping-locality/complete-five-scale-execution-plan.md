## Purpose and boundary

A new immutable execution is required to supersede the unmatched five-scale development
evidence. It must not extend, relabel, overwrite, seal, or promote either
`direct-embedded-rank2-controlled-v1` or `direct-embedded-rank2-controlled-v2`.

The proposed execution remains a synthetic finite numerical control. A passing
verification would establish bounded software-route agreement for its declared bytes. It
would not establish material validity, continuum convergence, publication acceptance,
or scientific validation. An unresolved installed momentum outcome is an admissible
scientific result and must not be converted into an execution failure or relabeled as
historical donor convergence.

The current immutable direct-v2 execution owns one five-member final-mesh parent

These owners compose existing rank-two analyzers and independent references. They do not

## Proposed lifecycle

Use three new module-scope, atomic, no-overwrite scripts:

1. `run_complete_01_calculation.py` constructs the new aggregate in a temporary sibling
   directory, proves canonical typed round-trip admission, writes result and execution
   metadata, and atomically renames the directory.
2. `run_complete_02_verification.py` admits exact calculation bytes, independently
   reconstructs every family member, momentum comparison, truncation channel, and
   minimum tolerance-satisfying support decision without calling the production
   owners, then writes canonical verification and its manifest atomically.
3. `run_complete_03_render.py` admits stored passing verification, authenticates the
   complete-scope summary projection, and renders a deterministic Markdown summary plus
   the closed scientific-story, sampled range-inflation, and separated error-channel PNG
   inventory without rerunning calculation or verification. The figures consume the
   admitted aggregate directly, read no development CSV, and are digest-bound by the
   rendering manifest.

The execution metadata must bind the calculation family, new execution identity, exact
result digest, producer-script digest, dependency versions, clean Git source revision,
evidence status, claim boundary, and `sealed: false`. Verification and rendering manifests must
bind their input bytes and script identities. Failure artifacts remain immutable and do
not authorize an in-place retry.

## Purpose

This maintained inventory catalogs every event family, immediate session or exercise directory, and named exercise or runnable example in the upstream `wannier-tutorials` Git tree. It identifies tutorial material that may inform `ksdft2effmass`; it does not activate a Task, authorize a calculation, select production settings, or establish scientific validation.

The catalog unit is an event, session, named exercise, separately runnable example, or explicitly enumerated example collection. Pseudopotentials, plots, reference outputs, notebooks, helper scripts, and generated data are materials of an entry rather than additional tutorials.

## Relevance classification

The catalog uses exactly these dispositions:

| Classification | Meaning here |
|---|---|
| `immediate_execution` | First tutorial reproductions proposed after separate execution authorization: the latest isolated Si valence and disentangled Si valence-plus-conduction exercises. |
| `immediate_fixture` | Already-produced compact artifacts suitable as software-verification fixtures without rerunning upstream software. |
| `near_term_method` | Directly informs the next method studies: SCDM, SAWF, dense interpolation, band derivatives, or effective-mass extraction. |
| `later_research` | Relevant to later automation, gauge/symmetry control, unfolding, projector choice, alignment, or real-space Hamiltonian construction. |
| `reference_only` | Useful background or an implementation example, but not currently needed in the proposed path. |
| `out_of_scope` | Electron--phonon, correlated-electron, topology/response, or transport work outside the authorized project scope. |

These are proposed uses, not evidence that a method is implemented, converged, suitable, or validated.

## Recommended path for `ksdft2effmass`

```text
current QEXSD periodic-record extraction
→ latest silicon isolated-valence Wannier tutorial
→ Wannier artifact inventory
→ silicon valence-plus-conduction disentanglement tutorial
→ parse H_W(R)
→ independently reconstruct H_W(k)
→ compare QE and Wannier bands
→ extract valley position and effective masses
→ study projection/SCDM sensitivity
→ study symmetry-adapted gauges
→ compare against parameterized sp3s* tight binding
```

This is a recommendation only. It does not change or activate any Task.

The latest isolated silicon exercise constructs **four bond-centered Wannier functions for the isolated valence-band manifold, without disentanglement**. The silicon valence-plus-conduction exercise constructs an **eight-function $sp^3$ Wannier representation using frozen and outer disentanglement windows**. That eight-function Wannier model is not the project's final parameterized orthogonal $sp^3s^\ast$ tight-binding model: the basis size, fitting constraints, parameterization, and intended comparison contract differ.

The existing QE Davidson smoke test uses the legacy `Si.pz-vbc.UPF` Perdew--Zunger LDA setup, whereas these Wannier exercises use `Si.pbe-n-van.UPF` with a PBE setup. Their densities, wavefunctions, energies, and reference zeros must not be mixed. Reproducing a tutorial establishes operational behavior only; it does not establish production convergence or scientific validation. Likewise, an existing `wannier90_hr.dat` can verify a parser and an independent Fourier reconstruction, but it cannot validate this project's projections, windows, gauge, localization, or other Wannierization choices.

## Tutorial artifact types

Artifacts have roles in a particular workflow; the extension alone does not establish completeness, compatibility, or scientific meaning. Not every tutorial generates every artifact.

| Artifact | Typical role | Taxonomy | Important boundary |
|---|---|---|---|
| `.win` | Human-authored Wannier90 parameters: cell, atoms, projections, windows, $k$ mesh, plotting/output requests | specification | Owns requested Wannierization settings, not the realized result. |
| `.nnkp` | Neighbor-$k$ list and interface request generated by `wannier90 -pp` | mechanical bridge | Connects the `.win` specification to an electronic-structure interface. |
| `.amn` | Projection amplitudes $\langle\psi_{m\mathbf{k}}\vert g_n\rangle$ | Bloch-space numerical data | Gauge- and projection-dependent input to initialization/disentanglement. |
| `.mmn` | Neighboring-$k$ overlaps between Bloch states | Bloch-space numerical data | Numerical overlap data used by localization; not $H_W(R)$. |
| `.eig` | Kohn--Sham eigenvalues on the Wannier mesh | Bloch-space numerical data | Carries energies under the parent calculation's reference convention. |
| `.wout` | Human-readable Wannier90 log and realized summary | Wannier result | Reports convergence, spreads, centers, warnings, and settings; it is not the sole retained numerical result. |
| `.chk` | Wannier90 native checkpoint for restart/post-processing | external binary/native artifact | Version/tool dependent; treat as opaque unless an owned reader contract exists. |
| `_hr.dat` | Real-space matrix elements $H_W(\mathbf R)$ with degeneracies | real-space operator | Primary compact represented Hamiltonian; requires basis, units, lattice, gauge, and energy-reference metadata. |
| `_band.dat` | Wannier-interpolated energies along a path | derived projection | Suitable for band comparison under matched path/order/reference conventions. |
| `_band.kpt` | $k$ points used for an interpolated band path | specification | Defines sampling coordinates; does not contain bands. |
| `_centres.xyz` | Wannier centers (and often atoms) for visualization | Wannier result | Useful localization output; coordinate convention must be retained. |
| `UNK*` | Real-space periodic Bloch functions on a grid for plotting/restart options | external binary/native artifact | Potentially large; not needed merely to parse `_hr.dat`. |
| QE SCF/NSCF inputs | Parent density and uniform/path Bloch-state calculation requests | specification | SCF and child NSCF lineage, mesh, bands, cutoffs, and reference must remain explicit. |
| Pseudopotentials | External core-model data consumed by QE | external binary/native artifact | Identity, checksum, XC, valence, relativity, and formalism are scientific provenance; never mix by element name alone. |
| Tutorial reference outputs | Expected logs, bands, centers, plots, checkpoints, or matrices supplied upstream | Wannier result, real-space operator, derived projection, or external binary/native artifact as applicable | Useful for software verification only under an identified file and acceptance rule; not production truth. |

`specification`, `mechanical bridge`, `Bloch-space numerical data`, `Wannier result`, `real-space operator`, `derived projection`, and `external binary/native artifact` are distinct roles. A directory can contain several roles, and a single calculation may omit optional outputs.

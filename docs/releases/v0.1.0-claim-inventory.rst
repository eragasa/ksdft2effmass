Classification rules
--------------------

``Included``
   The release may make the stated bounded claim because the candidate contains
   direct passing evidence for it.

``Provisional``
   The implementation or record may ship, but the release must not present it as
   a supported production or scientific capability.

``Excluded``
   The release makes no claim for the item.  Presence in source, documentation,
   calculations, a lockfile, or retained records does not change that status.

``Blocked``
   The claim cannot enter the release until the listed evidence or human decision
   is completed.  A green continuous-integration run alone cannot clear a human
   or machine-authority gate.

Explicitly prohibited interpretations
--------------------------------------

The release must not state or imply that:

* 5,273 passing tests prove scientific validity;
* the hosted runner performed production Quantum ESPRESSO, Wannier90, ABINIT,
  MPI, scheduler, HPC, or authorized ``minerva`` work;
* retained accepted records automatically validate recomputed results on a new
  machine;
* floating-point values are bit-for-bit portable where the documented oracle is
  tolerance-based;
* unavailable nonisolated eigenvector-overlap channels passed;
* dependency presence proves capability support;
* every module, research note, task, calculation, or decision in the repository
  is a stable public API or an endorsed release claim; or
* ``v0.1.0`` establishes material adequacy, uncertainty quantification, or
  transferability.

Authorized-machine rule
-----------------------

A new ``minerva`` execution is not required for this software-only claim set,
because production Stage C results and scientific conclusions are excluded.  If
review expands the release claims to include a new protected Stage C result,
that expansion is blocked until the separately authorized execution runs on the
accepted machine identity and its retained evidence receives human review.  A
portable synthetic test must never satisfy that gate.

Promotion rule
--------------

No checklist completion, CI result, draft pull request, or automated agent may
by itself authorize promotion.  ``main`` remains unchanged until a human accepts
the final claim inventory, resolves or defers every release-review finding, and
explicitly authorizes merge and signed tagging.
